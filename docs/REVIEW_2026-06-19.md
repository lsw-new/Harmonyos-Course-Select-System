# 全项目审查与优化报告 · 2026-06-19

由 agent team（4 个并行审查 agent）对 HarmonyOS（ArkTS）+ Node/Express/Postgres 教学管理系统做代码级审查，
覆盖后端安全、后端代码质量、前端 ArkTS、全栈性能四条线，并落地修复 + 部署 + 验证。

## 审查结论概览

- 架构层面无 CRITICAL：参数化查询、JWT 身份从 token 提取、选课/成绩/报名事务 + FOR UPDATE 行锁、
  管理端 fail-closed 细粒度权限均已正确实现。
- 真正高危集中在两点：前端「remote 登录拿不到 profile 回退 mock」导致张冠李戴/越权；
  打分接口不校验学生归属班级导致数据污染。两者均已修复。

## 已落地修复（4 个提交，全部已部署线上 + 验证）

### 第一批 后端安全与正确性 `fb8fae5`
- 打分接口校验学生归属教学班，拒绝向任意学号写成绩（数据完整性）
- pg 约束错误统一走分类安全文案（`errorHandler.pgClientError`），不再回 `e.message` 原文，堵 schema 泄露
- 登录账号状态异常不再回显数据库枚举值
- 注册/找回密码口令长度收紧 8–72（堵 bcrypt 72 字节截断旁路 + 提高下限）
- 评教提交 status UPDATE 补绑 student_id（防御纵深）
- 请假/反馈自由文本加长度上限、评教答卷加条目数与结构校验（防 DoS）
- 成绩打分逐人 INSERT → 单条 UNNEST 批量 UPSERT（47 次往返→1 次）
- 事务 COMMIT 后读回改用同一 client，不再混用 pool 另取连接
- 顺带修复 eval-period 两个历史失败用例（缺评教模板 mock）；全套 293 测试通过

### 第二批 数据库与查询性能 `b94e98c`
- 迁移 009：补齐缺失索引 class_students(class_name)、feedback_items(state,category)、feedback_items(student_id)
  （审查初稿建议的多数索引建表迁移里已存在，只补真正缺失三项）
- 管理仪表盘四组无依赖查询改 Promise.all 并行（响应 4×RTT→~1×RTT）
- 选课冲突周次交集用 Set 替代 indexOf 线性查找

### 第三批 前端认证与双轨一致性 `97be526`
- 登录（学生+管理端）：remote 拿不到真实 profile 即判失败，绝不用 mock 兜底（根除张冠李戴/越权）
- 管理端登录命中非 admin 账号直接拒绝
- 仪表盘 getDashboard remote 失败抛错走错误态，不再展示 mock 假统计
- 评教提交 remote 无登录学生时拒绝，不静默写 mock 本地缓存
- 打分输入改不可变更新（map 重赋值 @State 数组），符合不可变铁律
- HAP 构建通过

### 第四批 安全响应头 + 主键防碰撞 `7535070`
- 手写安全响应头中间件（零依赖）：nosniff / X-Frame-Options / Referrer-Policy /
  Permissions-Policy / HSTS（https）/ `/api` no-store——线上 6 头已验证生效
- `ids.genId()` 用 crypto.randomUUID 替代裸 Date.now() 生成主键（6 处），杜绝并发同毫秒碰撞 500

## 有意延后（记录在案，非本轮处理）

- nodemailer ≤9.0.0 升级：当前代码路径（无 raw/attachments/用户插入 HTML）不触发该 CVE；
  升级为 breaking 且需重传 node_modules，会动到邮箱验证码这一关键链路，故延后，单独评估。
- 后端「上帝路由文件」拆分（admin.routes ~660 行）、syncAllStudents N+1 事务批量化、
  权限中间件每请求查库改缓存、评教统计应用层聚合下推 SQL：均为较大重构，价值有限/风险偏高，延后。
- 前端 SchedulePage findLesson 每格多次调用：@Builder 不允许局部 const，改造需引入子组件，
  收益小（课表数组很小），暂不动。
- 暗色模式：长期延后（既有决策）。
